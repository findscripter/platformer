# 玩家流程开发流程清单

## 0. 开发目标

本清单用于把“玩家从点击界面开始到游戏结束”的流程拆成可执行开发任务。

核心目标：

```text
玩家点击开始 / 继续
↓
进入游戏
↓
游玩、暂停、死亡、切关
↓
通关或退出
↓
保存数据并返回主菜单 / 结束游戏
```

---

# 1. 启动与全局系统

## 1.1 BootScene 搭建

| 任务                          | 说明                  | 优先级 |
| --------------------------- | ------------------- | --- |
| 创建 BootScene                | 作为游戏启动入口            | 高   |
| 创建 Bootstrapper             | 负责初始化全局系统           | 高   |
| 设置 BootScene 为首个启动场景        | Build Settings 中排第一 | 高   |
| BootScene 初始化完成后跳转 MainMenu | 不直接进入游戏             | 高   |

## 1.2 全局管理器初始化

| 任务               | 说明                               | 优先级 |
| ---------------- | -------------------------------- | --- |
| GameStateManager | 管理 Boot、Menu、Loading、Playing 等状态 | 高   |
| SceneFlowManager | 统一处理场景加载、卸载、切换                   | 高   |
| UIManager        | 管理主菜单、暂停、结算、死亡界面                 | 高   |
| InputManager     | 封装 Input System 输入               | 高   |
| SaveManager      | 读取和保存游戏进度                        | 高   |
| AudioManager     | 管理 BGM 和音效                       | 中   |
| DataCollector    | 采集玩家行为数据                         | 高   |
| ConfigManager    | 加载关卡、对象、玩家配置                     | 中   |

## 1.3 初始化顺序

```text
BootScene
↓
Bootstrapper 启动
↓
创建或检查全局管理器
↓
加载本地设置
↓
加载存档索引
↓
初始化输入系统
↓
初始化 UI 系统
↓
初始化数据采集系统
↓
切换到 MainMenuScene
```

## 1.4 验收标准

```text
启动游戏后不会直接进入关卡
不会重复创建管理器
全局管理器跨场景不销毁
初始化完成后稳定进入主菜单
```

# 2. 主菜单开发

## 2.1 主菜单界面

| 任务               | 说明            | 优先级 |
| ---------------- | ------------- | --- |
| 创建 MainMenuScene | 主菜单场景         | 高   |
| 创建 MainMenu UI   | 包含开始、继续、设置、退出 | 高   |
| 开始游戏按钮           | 触发新游戏流程       | 高   |
| 继续游戏按钮           | 读取存档并进入游戏     | 高   |
| 设置按钮             | 打开设置界面        | 中   |
| 退出按钮             | 退出游戏          | 中   |

## 2.2 开始游戏流程

```text
点击开始游戏
↓
判断是否存在旧存档
↓
需要时弹出覆盖确认
↓
创建新存档数据
↓
初始化玩家初始状态
↓
初始化数据采集 Session
↓
进入 Loading
↓
加载第一个关卡
```

## 2.3 继续游戏流程

```text
点击继续游戏
↓
检查是否存在存档
↓
没有存档则按钮置灰或提示
↓
读取最近存档
↓
恢复玩家状态
↓
恢复当前关卡 ID
↓
进入 Loading
↓
加载目标关卡
```

## 2.4 验收标准

```text
开始游戏能进入第一个关卡
继续游戏能进入存档记录的关卡
没有存档时不会报错
返回主菜单后按钮状态正确
```

# 3. Loading 与场景流转开发

## 3.1 Loading 流程

| 任务            | 说明             | 优先级 |
| ------------- | -------------- | --- |
| 创建 Loading UI | 显示加载过程         | 高   |
| 场景加载封装        | 不允许各对象直接调用场景切换 | 高   |
| 淡入淡出效果        | 场景切换过渡         | 中   |
| 加载完成回调        | 通知游戏进入 Playing | 高   |

## 3.2 统一加载流程

```text
请求进入关卡
↓
GameState = Loading
↓
显示 Loading UI
↓
关闭玩家输入
↓
卸载当前场景
↓
加载目标 LevelScene
↓
加载关卡配置
↓
生成玩家
↓
生成 / 初始化场景对象
↓
绑定摄像机
↓
初始化 HUD
↓
GameState = Playing
↓
开启玩家输入
```

## 3.3 场景切换开发任务

| 任务                     | 说明                            | 优先级 |
| ---------------------- | ----------------------------- | --- |
| Level ID 定义            | 每个关卡唯一 ID                     | 高   |
| SpawnPoint 定义          | 每个出生点唯一 ID                    | 高   |
| SceneTransitionTrigger | 进入门、边界、传送点触发                  | 高   |
| 目标场景配置                 | 指向目标 Level ID 和 SpawnPoint ID | 高   |
| 当前场景状态保存               | 保存机关、收集物、敌人状态                 | 中   |
| 切换时锁输入                 | 防止重复触发                        | 高   |

## 3.4 验收标准

```text
点击开始后进入正确关卡
切换关卡不会重复生成玩家
切换过程中玩家不能操作
加载完成后摄像机正确跟随
HUD 正常显示
```

# 4. 玩家生成与控制流程

## 4.1 玩家生成

| 任务            | 说明                 | 优先级 |
| ------------- | ------------------ | --- |
| PlayerPrefab  | 玩家预制体              | 高   |
| PlayerSpawner | 根据 SpawnPoint 生成玩家 | 高   |
| SpawnPoint 组件 | 标记出生位置             | 高   |
| 玩家状态初始化       | 血量、能力、朝向、位置        | 高   |
| 复活点记录         | 保存最近检查点            | 高   |

## 4.2 玩家输入与动作

| 任务    | 说明          | 优先级 |
| ----- | ----------- | --- |
| 移动    | 左右移动        | 高   |
| 跳跃    | 普通跳跃        | 高   |
| 下落穿平台 | 单向平台需要      | 中   |
| 攻击    | 基础攻击        | 中   |
| 受击    | 扣血、硬直、无敌帧   | 高   |
| 死亡    | 血量归零 / 掉落死亡 | 高   |
| 交互    | 门、存档点、机关    | 中   |

## 4.3 玩家状态机

```text
Idle
↓
Move
↓
Jump
↓
Fall
↓
Attack
↓
Hurt
↓
Dead
```

暂停、加载、结算状态下，玩家输入必须关闭。

## 4.4 验收标准

```text
玩家能从出生点正确生成
玩家不会在切关后重复存在
暂停和死亡时不能继续控制
复活后状态正确恢复
```

| 收集物 | 拾取、保存状态               | 中   |
| 门   | 触发关卡切换                | 高   |
| 检查点 | 更新复活位置                | 高   |

## 6.2 非交互视觉层对象

| 类型  | 任务               | 优先级 |

# 7. 暂停流程开发

## 7.1 暂停菜单

| 任务        | 说明               | 优先级 |
| --------- | ---------------- | --- |
| 暂停输入      | Esc / Start 键    | 高   |
| 暂停 UI     | 继续、重新开始、设置、返回主菜单 | 高   |
| 冻结游戏逻辑    | 角色、敌人、机关暂停       | 高   |
| 保持 UI 可操作 | 暂停时 UI 输入仍可用     | 高   |

## 7.2 暂停流程

```text
玩家按下暂停
↓
GameState = Paused
↓
关闭玩家玩法输入
↓
冻结游戏时间
↓
显示暂停菜单
```

## 7.3 暂停菜单按钮

| 按钮    | 流程                                |
| ----- | --------------------------------- |
| 继续    | 关闭菜单 → 恢复时间 → GameState = Playing |
| 重新开始  | 确认 → 重置当前关卡                       |
| 设置    | 打开设置面板                            |
| 返回主菜单 | 确认 → 保存 → 卸载关卡 → MainMenu         |
| 退出游戏  | 确认 → 保存 → 退出程序                    |

## 7.4 验收标准

```text
暂停时玩家和敌人停止
暂停菜单能正常点击
继续后状态恢复
暂停时不会触发攻击、跳跃等玩法输入
```

# 8. 死亡与复活开发

## 8.1 死亡触发条件

| 条件   | 说明         |
| ---- | ---------- |
| 血量归零 | 被敌人 / 陷阱伤害 |
| 掉出地图 | 低于死亡高度     |
| 即死机关 | 尖刺、压板等     |

## 8.2 死亡流程

```text
触发死亡
↓
GameState = PlayerDead
↓
关闭玩家输入
↓
播放死亡动画
↓
记录死亡数据
↓
显示死亡 UI
```

## 8.3 复活流程

```text
点击复活
↓
读取最近检查点
↓
恢复玩家血量
↓
重置玩家位置
↓
重置部分敌人 / 机关
↓
隐藏死亡 UI
↓
GameState = Playing
↓
恢复输入
```

## 8.4 验收标准

```text
死亡只触发一次
死亡后不能继续操作玩家
复活后玩家位置正确
复活后血量正确
死亡数据被记录
```

# 9. 关卡完成与结算开发

## 9.1 完成条件

| 条件      | 用途            |
| ------- | ------------- |
| 到达终点    | 平台跳跃 Demo 最简单 |
| 击败 Boss | 后续扩展          |
| 收集关键物品  | 后续扩展          |
| 触发剧情事件  | 后续扩展          |

## 9.2 结算流程

```text
触发关卡完成
↓
GameState = LevelComplete
↓
关闭玩家输入
↓
停止计时
↓
保存通关进度
↓
汇总行为数据
↓
显示结算 UI
```

## 9.3 结算显示内容

| 内容    | 来源                       |
| ----- | ------------------------ |
| 通关时间  | DataCollector            |
| 死亡次数  | DataCollector            |
| 受击次数  | DataCollector            |
| 跳跃次数  | DataCollector            |
| 击败敌人数 | DataCollector            |
| 收集物数量 | SaveData / DataCollector |
| 综合评价  | 根据规则计算                   |

## 9.4 结算按钮

| 按钮    | 流程                   |
| ----- | -------------------- |
| 下一关   | 加载下一个 Level ID       |
| 重新挑战  | 重置当前关卡               |
| 返回主菜单 | 保存 → 卸载关卡 → MainMenu |
| 退出游戏  | 保存 → 退出程序            |

## 9.5 验收标准

```text
到达终点能进入结算
结算数据正确显示
结算时玩家不能移动
下一关或返回主菜单流程正常
```

# 10. 存档系统开发

## 10.1 存档内容

| 数据        | 说明       |
| --------- | -------- |
| 当前关卡 ID   | 继续游戏用    |
| 当前出生点 ID  | 玩家生成位置   |
| 玩家血量      | 可选       |
| 已解锁能力     | 后续扩展     |
| 已收集物      | 防止重复拾取   |
| 已打开机关 / 门 | 场景状态恢复   |
| 已击败敌人     | 可选       |
| 检查点 ID    | 复活位置     |
| 游戏设置      | 音量、按键、语言 |
| 对话进度      | `DialogueSaveData`：已完成对话、选项、标记、进行中快照、NPC once |

## 10.2 保存时机

```text
开始新游戏
到达检查点
拾取重要收集物
打开机关 / 门
切换关卡
完成关卡
返回主菜单
退出游戏
```

## 10.3 验收标准

```text
继续游戏能恢复到正确关卡
收集过的物品不会重复出现
检查点复活正确
返回主菜单再继续不会丢失进度
```

# 11. 数据采集系统开发

## 11.1 数据采集生命周期

```text
开始游戏
↓
创建 Game Session
↓
进入关卡
↓
创建 Level Session
↓
监听玩家行为
↓
玩家死亡 / 切关 / 通关时记录节点
↓
退出或通关时结束 Session
↓
导出或保存数据
```

## 11.2 需要记录的事件

| 事件               | 内容          |
| ---------------- | ----------- |
| GameStart        | 游戏开始时间、模式   |
| LevelStart       | 关卡 ID、出生点   |
| PlayerMoveSample | 玩家位置、速度、状态  |
| Jump             | 时间、位置、是否在地面 |
| Attack           | 时间、位置、方向    |
| Hurt             | 时间、位置、伤害来源  |
| Death            | 时间、位置、死亡原因  |
| Respawn          | 检查点 ID、位置   |
| Collect          | 收集物 ID、位置   |
| EnemyKilled      | 敌人 ID、位置    |
| Interaction      | 对象 ID、交互类型  |
| Pause            | 暂停开始 / 结束   |
| LevelComplete    | 通关时间、统计结果   |
| GameEnd          | 结束原因、总时长    |

## 11.3 数据采集原则

```text
数据采集只监听事件
不影响玩家控制
不参与玩法判断
不阻塞场景加载
关键事件实时记录
高频位置数据按固定间隔采样
```

## 11.4 验收标准

```text
一局游戏能生成完整 Session
死亡、跳跃、受击、通关数据能记录
退出游戏时数据不会丢失
数据结构便于后续 AI 分析
```

# 12. GameState 状态流转开发

## 12.1 状态定义

| 状态              | 说明    |
| --------------- | ----- |
| Boot            | 启动初始化 |
| MainMenu        | 主菜单   |
| Loading         | 加载场景  |
| Playing         | 正常游玩  |
| Paused          | 暂停    |
| SceneTransition | 场景切换  |
| PlayerDead      | 玩家死亡  |
| LevelComplete   | 关卡完成  |
| Result          | 结算    |
| GameOver        | 游戏结束  |
| Exit            | 退出    |

## 12.2 状态限制

| 当前状态            | 允许操作             |
| --------------- | ---------------- |
| MainMenu        | 点击菜单按钮           |
| Loading         | 禁止玩家输入           |
| Playing         | 移动、跳跃、攻击、交互、暂停   |
| Paused          | UI 操作，不允许玩法输入    |
| PlayerDead      | 死亡 UI 操作，不允许玩法输入 |
| SceneTransition | 禁止输入，等待切换完成      |
| LevelComplete   | 结算 UI 操作         |
| Result          | 返回、下一关、重开        |
| Exit            | 保存并退出            |

## 12.3 验收标准

```text
任何时刻只有一个主状态
暂停不能在 Loading 中触发
死亡不能在暂停时重复触发
场景切换不能被连续触发多次
结算后不能继续控制玩家
```

# 13. 推荐开发顺序

## 第一阶段：打通主流程

目标：从主菜单点击开始，进入关卡，能控制玩家，能到终点结算。

```text
BootScene
↓
全局管理器
↓
MainMenu
↓
Loading
↓
LevelScene
↓
PlayerSpawner
↓
基础移动跳跃
↓
Camera 跟随
↓
HUD
↓
终点触发
↓
结算 UI
```

验收结果：

```text
玩家能从主菜单开始一局游戏，并完成关卡看到结算。
```

---

## 第二阶段：补充暂停、死亡、复活

目标：完善一局游戏中的异常流程。

```text
暂停菜单
↓
重新开始关卡
↓
返回主菜单
↓
玩家受伤
↓
玩家死亡
↓
死亡 UI
↓
检查点复活
```

验收结果：

```text
玩家可以暂停、死亡、复活、重开、返回主菜单。
```

---

## 第三阶段：补充场景切换和存档

目标：支持多个场景和继续游戏。

```text
Level ID
↓
SpawnPoint ID
↓
SceneTransitionTrigger
↓
保存当前关卡
↓
保存检查点
↓
继续游戏
↓
恢复收集物 / 机关状态
```

验收结果：

```text
玩家可以跨关卡移动，退出后继续游戏能恢复进度。
```

```text
平台

陷阱

敌人
↓
收集物

机关
↓
门
↓
特效

音效

视差背景
```

验收结果：

# 16. 推荐里程碑

## Milestone 1：主流程跑通

```text
主菜单 → 开始游戏 → 进入关卡 → 移动跳跃 → 到达终点 → 结算
```

## Milestone 2：失败流程跑通

```text
受伤 → 死亡 → 死亡界面 → 检查点复活 / 重新开始
```

## Milestone 3：返回与继续跑通

```text
暂停 → 返回主菜单 → 继续游戏 → 恢复关卡
```

## Milestone 4：多关卡跑通

```text
关卡 A → 门 / 边界 → 关卡 B → 指定出生点
```

## Milestone 5：数据采集跑通

```text
开始游戏 → 采集行为 → 关卡结束 → 导出完整数据
```

最终开发顺序建议是：

```text
先打通玩家主流程
再补异常流程
再补多关卡和存档
最后完善数据采集和表现
```
