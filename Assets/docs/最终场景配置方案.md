# 最终场景配置方案

## 一、目标

场景配置系统的目标是：

把平台跳跃关卡从“写死在代码里”改为“由配置文件驱动”。

程序只负责读取配置、生成场景对象、绑定行为逻辑；具体关卡内容、场景层级、地形、平台、敌人、机关、收集物、视觉效果等都通过配置文件描述。

最终实现效果：

```text
关卡设计数据
    ↓
场景配置文件
    ↓
运行时加载器
    ↓
生成完整可游玩的关卡场景
```

## 二、场景配置总体结构

一个完整关卡可以拆成以下几类配置：

```text
SceneConfig
├── SceneBaseConfig          场景基础信息
├── LayerConfig              场景分层配置
├── TerrainConfig            地形配置
├── PlatformConfig           平台配置
├── ObjectConfig             场景对象配置
├── EnemyConfig              敌人配置
├── MechanismConfig          机关配置
├── CollectibleConfig        收集物配置
├── EffectConfig             粒子、光影、后处理配置
├── AudioConfig              音频配置
├── CameraConfig             镜头配置
├── SpawnConfig              玩家出生点与复活点配置
└── TransitionConfig         场景切换配置
```

## 四、场景分层方案

平台跳跃场景建议拆成 5 个主要层级。

| 层级 | 内容 | 是否参与碰撞 | 作用 |
|---|---|---:|---|
| 背景层 | 天空、远山、遗迹轮廓、远景建筑 | 否 | 提供环境氛围 |
| 中景层 | 墙体、树、柱子、雕像、装饰物 | 通常否 | 增强空间深度 |
| 交互层 | 地面、平台、敌人、机关、收集物 | 是 | 核心玩法区域 |
| 前景层 | 藤蔓、碎石、遮挡物、暗角 | 否 | 制造遮挡和画面层次 |
| UI 层 | 血量、地图、提示、任务信息 | 否 | 玩家信息反馈 |

### 4.1 层级配置示例

```json
{
  "layers": [
    {
      "id": "background",
      "name": "背景层",
      "order": 0,
      "parallaxFactor": 0.2,
      "collision": false
    },
    {
      "id": "midground",
      "name": "中景层",
      "order": 1,
      "parallaxFactor": 0.5,
      "collision": false
    },
    {
```

## 五、地形配置方案

### 5.1 地形的来源

地形分为两类：

```text
提前配置在场景里的地形
运行时根据配置生成的地形
```

### 5.2 提前配置在场景里的地形

适合以下内容：

```text
复杂的美术地形
手工摆放的地面
需要精细碰撞的场景
特殊结构地形
大型场景装饰
```

例如：

```text
遗迹大门
复杂洞穴轮廓
大型断桥
手工绘制的地面平台
特殊 Boss 房间地形
```

这种方式适合美术表现强、结构固定的区域。

### 5.3 Runtime 生成的地形

适合以下内容：

```text
规则平台
重复地砖
临时平台
可破坏地形
程序生成房间
根据难度动态调整的平台
教学关卡中的临时辅助平台
```

例如：

```text
连续地面块
矩形平台
移动平台
浮空平台
尖刺区域
落石区域
```

运行时生成并不是随机生成，而是根据配置文件中的数据生成。

### 5.4 地形配置示例

```json
{
  "terrain": [
    {
      "id": "ground_001",
      "type": "static_ground",
      "prefab": "Terrain/GroundStone",
      "position": { "x": 0, "y": -3, "z": 0 },
      "size": { "x": 20, "y": 1 },
      "layer": "interactive",
      "collision": true
    },
    {
      "id": "wall_001",
      "type": "static_wall",
      "prefab": "Terrain/WallStone",
      "position": { "x": -10, "y": 1, "z": 0 },
      "size": { "x": 1, "y": 8 },
      "layer": "interactive",
      "collision": true
    }
  ]
}
```

## 六、平台配置方案

平台是平台跳跃玩法的核心对象，建议单独配置。

### 6.1 平台类型

```text
StaticPlatform      静态平台
MovingPlatform      移动平台
OneWayPlatform      单向平台
FallingPlatform     踩踏后掉落平台
BreakablePlatform   可破坏平台
TemporaryPlatform   限时平台
```

### 6.2 平台配置示例

```json
{
  "platforms": [
    {
      "id": "platform_001",
      "type": "static",
      "prefab": "Platform/StonePlatform",
      "position": { "x": 4, "y": -1, "z": 0 },
      "size": { "x": 3, "y": 0.5 },
      "layer": "interactive"
    },
    {
      "id": "platform_002",
      "type": "moving",
      "prefab": "Platform/MovingStonePlatform",
      "position": { "x": 8, "y": 0, "z": 0 },
      "movePath": [
        { "x": 8, "y": 0 },
        { "x": 12, "y": 0 }
      ],
      "speed": 2.0,
      "loop": true,
      "layer": "interactive"
    },
    {
      "id": "platform_003",
      "type": "falling",
      "prefab": "Platform/FallingPlatform",
      "position": { "x": 15, "y": 1, "z": 0 },
      "fallDelay": 0.5,
      "respawnTime": 3.0,
      "layer": "interactive"
    }
  ]
}
```

## 十一、粒子、光影与全局效果配置

视觉效果不要写死在场景里，而是作为场景配置的一部分。

### 11.1 效果类型

```text
AmbientParticle     环境粒子
LocalParticle       局部粒子
GlobalLight         全局光照
LocalLight          局部光源
PostProcess         后处理
ScreenEffect        屏幕效果
WeatherEffect       天气效果
```

### 11.2 效果配置示例

```json
{
  "effects": {
    "globalLight": {
      "color": "#6A7F9A",
      "intensity": 0.7
    },
    "postProcess": {
      "enabled": true,
      "profile": "PostProcess/RuinsCold"
    },
    "ambientParticles": [
      {
        "id": "dust_001",
        "prefab": "Effect/DustParticle",
        "position": { "x": 0, "y": 2, "z": 0 },
        "areaSize": { "x": 30, "y": 10 },
        "density": 0.5,
        "loop": true
      }
    ],
    "localLights": [
      {
        "id": "torch_light_001",

        "color": "#FFAA55",
```

## 十六、运行时加载流程

```text
1. 进入 Gameplay 场景
2. SceneLoader 接收目标 sceneId
3. ResourceManager 读取对应 SceneConfig
4. SceneBuilder 开始构建场景
5. 获取 Gameplay 场景中的 SceneRoot
6. 获取 BackgroundLayer、MidgroundLayer、GameplayLayer、ForegroundLayer、EffectsLayer
7. 生成背景层对象到 Runtime_Background
8. 生成中景层对象到 Runtime_Midground
9. 生成交互层地形、平台、敌人、机关、收集物
10. 生成前景层遮挡物到 Runtime_Foreground
11. 应用光照、粒子、后处理到 EffectsLayer
12. 初始化镜头边界
13. 设置玩家出生点
14. 注册场景切换点与数据采集触发器
15. 开始游戏
```

## 十九、配置与预制体的关系

推荐采用：

```text
配置文件只描述“放什么、放在哪、怎么表现”
预制体负责“具体长什么样、有什么组件”
代码负责“如何读取、生成、绑定逻辑”
```

例如：

```json
{
  "id": "enemy_001",
  "enemyType": "crawler",
  "prefab": "Enemy/Crawler",
  "position": { "x": 12, "y": -2, "z": 0 }
}
```

对应关系：

```text
配置文件 enemy_001
    ↓
读取 prefab: Enemy/Crawler
    ↓
实例化 Crawler 预制体
    ↓
设置位置
    ↓
绑定巡逻路径、侦测范围、掉落组
```

## 二十一、数据采集与场景配置结合

场景配置中建议给关键区域和对象增加数据采集字段。

例如：

```json
{
  "id": "platform_002",
  "type": "moving",
  "prefab": "Platform/MovingStonePlatform",
  "position": { "x": 14, "y": 0, "z": 0 },
  "analytics": {
    "track": true,
    "tag": "first_moving_platform",

  }
```

可记录：

```text
玩家是否到达该平台

玩家是否多次跳跃失败
玩家停留时间
```

敌人也可以配置：

```json
{
  "id": "enemy_001",

    "track": true,
```

可记录：

```text
玩家首次遇敌时间
是否击败敌人
被敌人攻击次数
是否死于该敌人
通过该区域所用时间
```

## 二十二、最终推荐方案

最终建议采用：

```text
Unity 场景作为运行容器
JSON 作为关卡配置文件
Prefab 作为对象模板
SceneBuilder 作为运行时生成器
LayerManager 管理分层与视差
ObjectSpawner 统一生成玩法对象
EffectSpawner 统一生成视觉效果
DataCollectionManager 接入关键对象与区域
```

也就是：

```text
场景 = 基础 Unity Gameplay 场景 + SceneConfig 动态生成内容
```

不要为每个关卡单独制作一个完整 Unity Scene，而是使用一个通用 Gameplay 场景，通过不同的 SceneConfig 生成不同关卡。

## 二十三、最终结论

最终场景配置方案如下：

```text
1. 使用统一 Gameplay 场景作为承载容器。
2. 每个关卡对应一个独立 SceneConfig JSON 文件。
3. SceneConfig 中配置场景基础信息、层级、地形、平台、敌人、机关、收集物、效果、镜头和切换点。
4. 运行时通过 SceneLoader 读取配置。
5. 通过 SceneBuilder 按层级生成场景内容。
6. 背景层、中景层、前景层只负责视觉表现。
7. 交互层负责地形、平台、敌人、机关、收集物和碰撞。
8. 地形可以手工预制，也可以根据配置运行时生成。
9. 粒子、光影、后处理作为 EffectConfig 扩展。
10. 数据采集通过 analytics 字段挂接到关键对象和区域。
```

最终架构可以概括为：

```text
SceneConfig 配置数据
        ↓
SceneLoader 读取配置
        ↓
SceneBuilder 构建场景
        ↓
LayerManager 创建层级
        ↓
ObjectSpawner 生成对象
        ↓
EffectSpawner 应用视觉效果
        ↓
DataCollectionManager 记录玩家行为
```

该方案适合当前项目的 Demo 阶段，也方便后续扩展为更复杂的类银河恶魔城地图结构。
