# 梦墟关卡接入与随机化交接说明

交付基线：Dreamremains-ArtSampleB / Git 1def8e3。用户已认可当前路线。2026-09-12。

## 1. 这个包怎么用
完整“可打开的关卡样例 Unity 工程”，包含 Assets、Packages、ProjectSettings、QA；不含 Library、Temp、Logs、.git。重新打开会重新导入。它是参考工程，不是可直接覆盖对方最新 UI/AI 工程的补丁，也不是独立无依赖 unitypackage。
请以程序的最新 UI/AI 工程为集成主体，在独立分支合并本包关卡相关代码、美术及 .meta。先运行默认固定版核对，再接随机，不重新生成整张地图。
不要整体覆盖 Assets、PersistentRoot、GameLoop、UIManager、PlayerController、输入、场景列表、Packages 或 ProjectSettings。共享类需要对比合并：死亡扣血/复活、镜头、攻击、交互、塔罗状态与结束流程等，不能只复制一个 Gameplay.unity。
本包的“完整”指该关卡副本的工程文件完整，不代表已合并程序最新 UI/AI，也不代表已验收所有随机组合。

Assets/Game/Scripts/Level/DreamremainsLevelData.cs：原始紧凑布局和结构定义。
Assets/Game/Scripts/Level/DreamremainsExpandedLayout.cs：当前实际认可的展开路线，包括平台、分支、机关、怪物和补给点。静态初始化会调用 Expand，不能直接拿前者原始坐标施工。

本交付附有“实际展开关卡数据.json”和“实际点位.csv”，由当前两个布局源文件执行导出；包含 A 83 平台、B 82 平台，4 碎片。CSV 只是导航表，完整移动端点、尖刺、深渊、区域等以 JSON/代码为准。
坐标：图纸 Y 向下，Unity 平台顶面 Y=8-Y；平台根节点 Y=顶面-.2；平台世界X=场景起点+X+W/2。A 起点0，B起点170。普通 Point 根Y=8-Y+.15。运行时有个别敌人支撑纠偏及移动/升高，导出值不能代替 Play 中的最终物理位置。
ID 必须稳定。请不要凭设计图重新猜点位，也不要用对象数组序号作为存档身份。

## 3. 在哪里加入区域随机
RT-01～09 是区域/镜头边界，不是已完成的 RandomSlot，不等于4个塔罗阶段。
LINK-A1～A4、LINK-B1～B4 是八段人工设计的连接路段，可作为局部模块候选范围，具体入口/出口和内部ID见附表。它们跨越/交叠其他上下分支，禁止按X矩形把所有对象一起删掉重建。
建议第一版锁住每段首尾平台、T1～T4、CP、A/B转换、END、主支线连接，以及现有布景主体。先随机低风险参数/同规格组合，不在整段任意撒平台。
模块替换必须连同对应敌人巡逻、尖刺、补给、专属装饰和引用关系一并验证。原固定默认模块永远作为失败回退。
重要：目前没有完成并验证 A/B/C 三套可换模块，没有一个现成 RandomSlot 脚本等着填参数。不能把这八段描述为已完成的随机系统。
建议新增每局的布局装配器：从固定 SceneSpec 克隆本局数据 → 按 seed 选择已验证模块 → 完成引用/可达性校验 → Bootstrap 实例化。避免在静态 SceneA/SceneB 上直接修改，不在 Update/每次进区域/复活时重抽。
seed、模块ID、激活候选点ID写入本局状态；死亡沿用同局布局，重新入梦才重抽。外观背景/山体不能由各组件独立 Random.Range 摆放。

## 4. Excel怎样接到关卡
以附带《塔罗牌机制组合_肉鸽规则更新版.xlsx》为机制源，结合下文用户最新确认。不是让 Excel 根据坐标直接生成地图。
现有入口：PlayerGuide/TarotCatalog.cs（牌及正逆位→E编号）、TarotEffectId.cs（效果/冲突通道）、TarotResultData.cs（本局牌组与激活状态）、Interaction/TarotNodeInteractable.cs（按序激活）、PlayerGuide/TarotEffectApplier.cs（应用角色/敌人/门效果）、Level/TarotZoneQuery.cs（区域载体查询）。
E00无变化；E01→AirWalkVolume；E02→SpikeTrap伤害豁免；E03→玩家跳跃；E04→攻击范围；E05/E17→玩家空中攻击模式；E06→指定捷径HiddenPathController；E07→玩家血量/HUD；E08/E10/E11→D1/D2/D3可选门；E09→尚未激活节点提示；E12/E18→FadingPlatform；E13→玩家左移限制；E14→SpikeGrowth；E15→RaisePlatform；E16→PatrolEnemy耐久。
角色类效果不应被误做成随机地形；地形效果只作用于事先标记的载体。E15当前升高上限约1.6、E14尖刺增长.7，移动平台有明确端点，前景和跳跃净空必须覆盖完整变化范围。未来参数变化必须重新测。
机制生效与布局抽样分开：抽中一张牌不等于生效；激活对应槽才生效。4张无重复，独立正逆位；E12/E18、E05/E17禁配。基础主线保留，完成4次激活才可结算，第四次后保留体验路段。
目前 TarotZoneQuery.HasEffect 读取本局已激活效果，因此回到旧区域仍持续；虽然有区域快照数据，不能误认为当前以快照锁死旧区域机制。新增“区域模块选择快照”也不能截断 Excel 要求的牌效持续。

## 6. 美术与随机的约束
固定层：A/B主背景、主体山体、大构图与固定安全水岸。
组件视觉层：跟随平台的 Transform/显隐/Collider 对齐，不能把碰撞外形和美术外形拆开变。
局部模块层：只携带本模块专属装饰；隐藏路线显隐与其引用的装饰同步。水面等环境不应盲目跟随升降台上下移动。
可随机装饰池：少量飞虫、淡雾、小草等有上限且避开主路线/交互物焦点。前景和视差必须预留变化后的落点与尖刺可见性。
副本尚未进行本轮提出的美术深化，先以现在画面为程序接入基线。
