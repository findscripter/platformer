## 完整流程（10 个主要 Frame）

### Frame 1｜梦境空间生成
- **视觉**: 深色星空背景，中央下方蓝色发光圆形区域（生成动画落点）
- **文本**: 顶部"梦境空间"，底部"梦境空间生成动画"
- **交互**: 自动播放生成动画
- **跳转**: → Frame 2

### Frame 2｜主梦泡可点击
- **状态**: 缺失独立分镜（可能合并到 Frame 1 或 3）
- **推测内容**: 梦泡出现，等待玩家点击
- **跳转**: → Frame 3

### Frame 3｜梦境残响播放
- **状态**: 缺失独立分镜
- **推测内容**: 点击梦泡后播放音频/视觉残响效果
- **跳转**: → Frame 4

### Frame 4｜梦泡消散留下梦核
- **视觉**: 
  - 左侧：角色站立姿态（Feifei？）
  - 中央：发光的梦核（球形，悬浮状态）
  - 底部：梦境空间背景延续
- **动画**: 梦泡消散粒子效果，梦核显现
- **交互**: 自动播放
- **跳转**: → Frame 5

### Frame 5｜腓腓入场捧梦核
- **视觉**: 
  - 中央：Feifei 角色从屏幕右侧进入
  - 梦核位置：中央偏上
  - 动作：Feifei 走向梦核并捧起
- **动画**: 角色入场行走动画 + 捧起动作
- **音效**: 脚步声、拾取音效
- **交互**: 自动播放
- **跳转**: → Frame 6

**状态**: 拆分为 8 个子分镜（6-1 至 6-8），见「补充｜Frame 5-6 细化分镜与需求」

- **UI**: 对话框出现（位置、样式待确认）

### Frame 7｜输入梦（第一次相遇对白后续）
- **视觉**: 
  - Feifei 站立等待姿态
  - UI：输入框出现（可能在屏幕底部或中央）
- **交互**: 玩家输入文本（梦境描述）
- **功能**: 捕获玩家输入 → 传递给后续流程
- **跳转**: → Frame 8

### Frame 8｜写梦与必要补问（同一问话框）
**状态机设计**: Frame 8 是一个双状态容器

#### 状态 A｜写梦｜统一问话框
- **UI**: 统一问话框显示
- **内容**: Feifei 提示玩家"写下你的梦"
- **交互**: 等待玩家输入

#### 状态切换箭头：A → B（原位切换）

#### 状态 B｜腓腓补问｜复用统一问话框
- **UI**: 同一问话框内容更新（不重新打开）
- **内容**: Feifei 根据玩家输入进行必要的追问
- **交互**: 玩家补充回答
- **跳转**: → Frame 9

**技术要点**:
- 同框切换 = 不销毁 UI，只更新文本和按钮状态
- Frame 8 trigger、Frame 8 title 是触发逻辑标记

### Frame 9｜塔罗抽牌
- **视觉**: 
  - 塔罗牌展示区域
  - 可能有多张牌供选择
- **交互**: 玩家点击选择一张塔罗牌
- **动画**: 抽牌动画、翻牌效果
- **跳转**: → Frame 10

**细化版本**（Frame 9 细化｜塔罗抽牌与 Fade）:
- 包含淡入淡出（Fade）过渡效果

### Frame 10｜关卡结束与梦核回应
- **视觉**: 
  - 梦核发光或产生反馈动画
  - 可能显示"关卡完成"/"新手引导结束"提示
- **内容**: 
  - Feifei 的结束语
  - 梦核的视觉/音效反馈
- **交互**: 
  - 自动播放结束动画
  - 点击"继续"进入主游戏/下一关
- **跳转**: → 主菜单 或 Gameplay

**细化版本**（Frame 10 细化｜关卡结束与梦核回应）:

## 从截图提取的补充信息

### Frame 6 细化结构
Frame 6 实际上被拆分成 **6-1 至 6-8 八个连续子场景**，每个子场景是一个对话/交互片段。从 `frame_05_06_detail.png` 可见：
- 6-1: Feifei 初次对话开场
- 6-2: 介绍梦核的作用
- 6-3: 询问玩家是否准备好
- 6-4: 引导玩家观察梦境空间
- 6-5: 解释"写梦"的概念
- 6-6: 提示输入方式
- 6-7: 鼓励玩家表达
- 6-8: 过渡到 Frame 7（输入环节）

**技术实现**: 用一个 `DialogueData` 资源包含 8 个连续节点，`DialogueManager` 顺序播放。

### Frame 9 细化结构（塔罗抽牌）
Frame 9 包含 **状态 A-F 六个子状态**（从 `frame_09.png` 观察到）：
- **状态 A**: 引导抽牌（Feifei 介绍规则）
- **状态 B**: 牌阵与对齐测试（显示 4 张牌背，排列整齐）
- **状态 C**: 第一次点牌（玩家点击第一张）
- **状态 D**: 继续选牌（提示"还可以选 3 张"）
- **状态 E**: 第二至第四张（玩家依次选择）
- **状态 F**: 四张同时展示（翻牌动画，展示结果）

**技术实现**: 状态机驱动，每个状态控制 UI 显示 + 玩家交互权限。

### 四栏需求表内容（部分可读）

#### 美术需求
- Feifei 角色 sprite（站立、行走、捧梦核、对话表情变化）
- 梦核 sprite（idle 发光、被捧起、回应状态）
- 梦泡 sprite（完整形态、消散动画帧、粒子效果）
- 对话框 UI（边框、背景、文字区域）
- 背景（星空渐变、梦境氛围粒子层）
- 塔罗牌（至少 4 张不同卡面 + 统一牌背）
- 输入框 UI（文本框、提交按钮、占位符文字样式）

#### 动效需求
- 梦境空间生成动画（粒子从中心扩散）
- 梦泡消散效果（alpha 渐变 + 缩放 + 粒子飘散）
- Feifei 入场（从右侧 slide in + ease out）
- 捧梦核动作（角色动画 + 梦核跟随）
- 对话框淡入淡出（0.3s ease）
- 塔罗牌翻转动画（3D 旋转 180°）
- 输入框弹出/收起（scale + alpha）

#### 音效需求
- 环境音：梦境氛围 loop（低频 pad + 轻柔钟声）
- 梦泡消散：玻璃破碎 + 低音震颤
- Feifei 脚步声：轻盈脚步 x2-3
- 拾取梦核：轻盈的"叮"声 + 回响
- 对话框弹出：轻快的"啵"声
- 塔罗牌翻转：纸张翻动声
- 输入确认：柔和的按钮音

#### 程序需求（交互逻辑）
- Frame 1-5: 自动播放序列（Timeline 或状态机自动转换）
- Frame 6: 对话系统支持 8 段连续文本 + 点击继续
- Frame 7: InputField 捕获文本 → 保存到 `GameContext` 或 `DialogueProgressService`
- Frame 8: 双状态 UI 切换（同一框体，内容替换）
  - 状态 A → B 的触发条件：玩家提交输入后，检查是否需要追问
  - 追问逻辑：文本长度 < 10 字 或 包含"不知道"/"随便" → 触发状态 B
- Frame 9: 塔罗选择交互
  - 4 张牌 button，点击后标记已选 + 播放翻牌动画
  - 选满 4 张后自动进入状态 F（展示）
  - 选中顺序影响后续剧情？（待确认）
- Frame 10: 结束演出 → `SceneTransitionManager.LoadScene("MainMenu")` 或 `"Gameplay"`
